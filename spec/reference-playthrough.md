## 3. 已确认的基础 UI

- 左上是四行参与者列表，包含棋子色标/缩略图、头像或名称，以及当前持有道具的小图标。
- 当前行动者同时通过列表色条、棋子描边、棋子上方头像气泡和中央回合横幅提示。
- 右侧显示当前轮次和少量系统入口，没有常驻大型操作面板。
- 当前主动道具以倾斜卡片停靠在右下，点击后棋盘压暗并打开底部操作层。
- 两颗移动骰位于棋盘下方偏中间；骰子定格后会显示醒目的点数总和。
- 地标触发使用横贯棋盘的名称横幅，随后才切入事件舞台。
- 终局不使用普通居中弹窗，而是独立的横向结果舞台。

这些状态是 `visual-design.md` 的桌面 UI 基线。网页实现可以提高文字尺寸、留白和动画清晰度，但不应改成传统三栏仪表盘。

## 4. 道具流程观察

开局画面可辨认三件样本道具：

- **备用骰子**：主动，使用后重新投掷。
- **鱼类被动道具**：清除自身暂停效果；录像文字不足以作为最终命名依据。
- **杂肉烤串**：主动，使用后前进 6 格。

录像还确认：每名参与者在左侧列表中有独立道具状态；本地当前主动道具在右下显示；点击后先查看效果与短对白，再选择返回或使用。

网页版只把这些当作首批内容样本。道具池继续通过配置扩展，AI 和远程玩家使用与本地玩家相同的使用命令。

## 5. 疯人院事件观察与改编

疯人院事件层一次展示三张牌：两张直接产生暂停等结果，一张带检定门槛并在成功、失败时进入不同分支。录像中的检定牌标为“智力事件”，显示了 `14` 门槛、额外修正信息和超出标准两骰范围的表现，说明原作依赖角色属性或其他加成。

网页版不复刻这套属性结构：

- 删除“智力、力量”等角色属性标签和所有角色修正值。
- 默认检定使用公开的两颗六面骰，门槛必须在 `2-12` 的可达范围内。
- 道具或临时规则可以要求重掷、改变骰组或改变取值方式，但结果仍只由画面上公开的骰子决定。
- 保留三张卡的风险差异、成功/失败分支、指定其他参与者等玩法表达。
- 所有卡牌效果使用结构化 `GameEffect`，不能把逻辑写进卡面组件。

## 6. 移动与终局观察

- 骰子定格后，亮色曲线从当前格沿实际路线延伸到目标格，并圈出目标位置。
- 棋子沿格子路径逐步移动，不是从起点瞬移到终点。
- 事件产生的额外移动也会显示路线，并使用与普通移动一致的落点处理。
- 多枚棋子可以靠得很近，因此同格或相邻格的错位、描边和层级是必要状态。
- 终局演出先抽象棋盘为横向地标进度线，再展示冠军和四人名次。

本项目已另行确认喧声屋覆盖第 `63、64、65` 格，进入其中任意一格立即获胜。录像不能覆盖这一明确决策。

## 7. 不进入网页版的内容

- 角色属性、属性检定修正、角色技能。
- 角色等级、经验、称号、装备或其他养成。
- 棋子皮肤的稀有度、解锁成长和规则加成。
- 结算货币和与角色成长绑定的奖励。

上述内容永久排除，不建立占位字段或空接口。

## 8. 必须保留的扩展能力

- 四个座位均可绑定本地、AI 或未来的远程控制器。
- 地图、格子数量、胜利格、地标和允许内容由 `MapDefinition` 配置。
- 事件、道具、临时规则和模式由版本化内容 ID 与规则集组合。
- 玩家命令、随机结果、领域事件和快照可以序列化、重放和恢复。
- 联机版本采用权威主机/服务器；客户端动画不阻塞权威回合推进。

这部分不是“未来可能重构”的愿望，而是当前实现必须遵守的边界。
