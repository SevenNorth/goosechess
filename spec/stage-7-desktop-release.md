# 阶段 7 桌面版发布质量报告

## 1. 发布体验

验证日期：2026-07-29。

- Pixi 棋盘在资源加载期间显示真实百分比和进度条；失败时保留 setup 状态并提供鼠标可用的重新加载入口，不显示无反馈的空白 Canvas。
- 表现设置提供 `0.75x`、`1x`、`1.5x`、`2x` 动画速度和镜头运动开关。镜头只改变 Pixi 表现，不进入规则、快照或 AI。
- 页面小于 `1180 x 680` 或处于竖屏时显示明确的桌面横屏提示，不实现竖屏布局。
- 图标命令具有 `title` 和 accessible name；玩家名使用省略和原文 tooltip，事件、道具和终局标题允许长词换行。
- 移除 Google Fonts 网络依赖。离线对局只加载同源静态资源，不发送游戏 API、XHR 或 WebSocket 请求。
- 动画 12 秒超时、页面失焦快进、失败快进和 restart 都回到最新 authority 快照。

## 2. 性能与资源

Pixi renderer 的 device pixel ratio 上限为 `2`。66 格、地标和纸面背景被烘焙为静态缓存纹理，棋子主体也使用缓存纹理；动态路线、目标圈、跳跃和终局效果仍独立绘制。

硬件加速 Chromium，NVIDIA GeForce GTX 1650 / D3D11：

| 视口 | 平均帧率 |
| --- | ---: |
| `1280 x 720` | 60.5 FPS |
| `1920 x 1080` | 60.3 FPS |

无头 CI 使用 SwiftShader 软件渲染，不作为目标设备帧率。自动化在该环境设置 10 FPS 的严重退化下限；硬件渲染仍要求至少 50 FPS。

生产构建资源：

| 范围 | Raw | Gzip |
| --- | ---: | ---: |
| 首屏 shell | 392.8 KiB | 118.6 KiB |
| 完整发布目录 | 2350.6 KiB | 1637.4 KiB |

`npm run check:release` 同时执行体积预算和文件禁入检查，拒绝参考截图、录屏、临时帧、调试种子资源及视频文件进入发布目录。

## 3. 稳定性

`npm run e2e:stability` 默认执行 30 分钟；`npm run e2e:stability:smoke` 执行 6 秒机制检查。长跑关闭 Playwright trace，避免数千次操作本身占用大量内存，关键 E2E 仍保留失败 trace。

最终 30 分钟结果：

- 同一浏览器上下文连续完成并重开 71 局 `1v3`。
- 每 10 秒采样，共 170 组 scene、ticker、资源、监听器和 tween 诊断。
- 强制 GC 后 JS heap 从 47.4 MB 增至 64.0 MB，增长 16.6 MB，低于 40 MB 门限。
- 收尾状态为 1 个 scene、1 个 ticker handler、11 个地图纹理、0 个窗口监听器、0 个 tween。

长跑在开发期间发现并修复已完成 tween 未从 Group 移除的问题，以及 Pixi 初始化失败时错误销毁未初始化 Application 的问题。

## 4. 自动化与 CI

`.github/workflows/release-quality.yml` 在 push 和 pull request 上执行：

```powershell
npm ci
npm run typecheck
npm run lint
npm run test
npm run validate:content
npm run check:versions
npm run build
npm run check:release
npm run e2e:ci
```

`spec/version-baseline.json` 保存协议 schema、规则实现和内容定义的版本与 SHA-256 基线。对应文件变化但 `PROTOCOL_SCHEMA_VERSION`、ruleset version 或 content version 未升级时，CI 失败。

Playwright 覆盖三个模式鼠标开局、固定种子终局、63/64/65 获胜、加载进度、资源失败重试、设置、最低尺寸提示、2x DPR、目标分辨率帧率、失焦快进、20 次 Pixi 重建和完整阶段 6 回归。

## 7. 3D 双骰增量验收

验证日期：2026-07-30。

- Three.js 双骰通过独立异步模块加载，不进入准备页首屏；本次生产构建首屏为 `418.5 KiB raw / 124.4 KiB gzip`，完整发布目录为 `2860.1 KiB raw / 1764.3 KiB gzip`，继续满足发布预算。
- `1280 x 720` 与 `1920 x 1080` 均验证骰子停靠在底部中央、点击区域与画面一致、滚动阶段移动到棋盘中央，并保存停靠与定格截图。
- `1280 x 720` 与 `1920 x 1080` 的中央高速旋转阶段均验证双骰随飞行从左右各 0.62 平滑展开到左右各 1.0 个逻辑单位，模型轮廓保持分离；底部停靠位置不变。
- Playwright 直接读取 Three.js WebGL 帧缓冲，确认底部停靠区域和滚动中的中央区域均有非透明像素，排除透明空画布或只存在 DOM 点击层的情况。
- 骰子只消费权威 `dice-roll` 提示；定格点数与合计使用同一结果，不在表现层生成规则随机数。路线、目标和棋子移动仍在骰子定格后串行播放。
- 失焦中断会取消 3D 动画并使旧播放版本失效，不允许已取消的 Promise 再写回路线阶段；失焦快进、阶段顺序和三个固定种子终局回归通过。
- 全仓 76 项单元测试、stage 6 的 9 项 Chromium 用例、stage 7 的 15 项发布用例、类型检查、lint、包边界、生产构建和发布体积检查通过。

### 7.1 总点数飞行动画

- 骰子定格阶段只显示一个红色总点数，不再显示“单骰 + 单骰 = 总数”的算式；可访问名称同步简化为“骰子结果 N”。
- 中央总点数以 216 像素前景文字和 280 x 280 像素容器覆盖在两颗 3D 骰子之上；飞行终点使用 0.31 倍缩放，仍保持原有纸张右下角视觉尺寸。
- 骰子在滚动阶段前约 28% 完成到中央的快速位移，途中由慢加速到高速翻滚；28%-67% 在中央保持高速，67%-80% 连续减速，最后 20% 平滑进入权威点数姿态。
- Playwright 在普通 `1x` 点击后约 700 毫秒读取中央 WebGL 帧，验证骰子已到达中央；随后分别间隔 400 毫秒和 300 毫秒再次读取并比较帧指纹，验证高速持续旋转与后续减速阶段都没有提前停住。
- 每颗骰子保存投掷前、翻滚结束和权威落点三个四元数关键姿态，使用主抛物线、两次递减弹跳、横向分离和衰减摇摆完成连续插值，首帧与停稳帧均不得发生姿态跳变。
- 普通速度下，骰子用约 1.82 秒滚动并定格，中央大号总点数继续停留约 580 毫秒；进入 `routePreview` 后再用约 1.4 秒按与路线绘制相同的速度系数飞行，保证玩家能够读清结果。
- `prefers-reduced-motion` 使用约 2.4 秒的低旋转、低弹跳投掷和约 1 秒的无抬升简化飞行，不再沿用原先 220 毫秒投掷与 0.01 毫秒飞行的不可读快进。
- 飞行动画具有明确的弧线抬升、旋转、缩放和运动投影，结束后以更大的字号停在纸张右下角，不能直接切换位置。
- 右下角目标坐标跟随棋盘纸张边界计算，结果必须落在纸张内的标注区域；宽屏下不能进入纸张外侧桌面或窗口黑色边栏，3D 骰子同时退出中央画布。
- 总点数穿过 `targetEmphasis`、`routeFade` 和 `moving` 阶段保持可见，只在棋子移动完成、表现队列回到 `ready` 后清除。
- 当前道具卡在结果飞行和移动期间暂时淡出，释放右下角结果位置；回到等待行动后恢复，不改变道具状态或可用命令。
- Playwright 在 `1280 x 720` 与 `1920 x 1080` 记录 `is-centered → is-corner` 状态序列，并按纸张响应式坐标精确验证最终落点、路线阶段 3D 画布清空、移动结束后结果消失和道具卡恢复。
- URL 动画速度参数与设置面板保持一致，最低接受 `0.75x`；红色结果位移时长随动画速度缩放，减少动态效果时继续使用全局最短过渡。

## 8. 道具隐私与消耗演出增量验收

验证日期：2026-07-30。

- 其他参与者的 HUD 不显示道具名称、“无道具”状态或“道具保密”占位文字；本地玩家仍可从右下卡片查看自己的完整道具。
- 协议升级为 v4、规则集升级为 v5、内容版本升级为 `2026.07.30.3`，并新增有序 `item-use` 提示；主动使用、检定保底、暂停防护和碰撞防护均在对应规则效果之前发出提示。
- 本地道具从右下道具栏飞入中央，其他玩家道具从画面上方飞入；中央卡片展示玩家名、主动/被动类型、道具名称和效果说明，随后沿竖直锯齿裂口分成左右两半消失。
- 普通 `1x` 时长约 3800 毫秒并随表现速度缩放；完整卡片在中央保留约 1.7 秒供阅读，再依次播放自上而下的裂口和左右分离。失焦或表现超时会同时取消道具与骰子演出，不阻塞快照恢复。
- `prefers-reduced-motion` 使用相同时长，降低入场与分离幅度但保留裂口和撕裂；不再沿用 700 毫秒闪现和无撕裂分支。
- Playwright 在 `1600 x 900` 的减少动态效果模式下验证对手 HUD 没有道具状态文字、演出时长为 3.8 秒且裂口可见，冻结撕裂阶段检查左右两半使用互补多边形裁切且位移方向相反，并保存竖向撕裂截图。
- 事件获得道具时，本地已有道具继续使用二选一确认，5 秒后提交当前勾选项且切换选择不重置倒计时；本地道具栏为空时显示单卡确认并在 3 秒后关闭，不提交额外规则命令、不产生 `item-use` 动画，确认期间暂停电脑表现。
- Playwright 固定种子验证二选一倒计时最终保留最后勾选的新道具，并使用“坏藤壶 → 走失的猫”的稳定路径验证单卡确认只在本地出现、3 秒后自动关闭。

## 9. 行动顺序 HUD 增量验收

验证日期：2026-07-30。

- 左上参与者 HUD 使用权威最终行动顺序从上到下排列，不再沿用固定座位顺序。
- 权威快照可以立即推进以保证电脑决策和合法命令不被表现阻塞，但 HUD 高亮与“当前行动”横幅使用独立的表现状态；棋子移动、碰撞及相关效果演出结束后才同步到下一位玩家。
- Playwright 固定种子验证 HUD 名称顺序与座次投掷产生的最终顺序一致，并验证掷骰后动画进行期间仍高亮当前玩家、完整表现结束后才高亮下一位。
