# 鹅了个棋网页版规格

更新日期：2026-07-30

## 文档目的

本目录定义“鹅了个棋”网页版重制的产品、玩法、技术和视觉基线。当前 `src/` 中的版本是规则验证原型，后续实现应以这里的规格为准。

## 当前结论

- 第一阶段只支持桌面浏览器，设计基准为 `1600 x 900`，最低支持 `1280 x 720`。
- 第一阶段只设计横向界面，不考虑竖屏布局。
- 第一阶段先实现人机对抗，开局可选择 `1v1`、`1v2` 或 `1v3`，即一名本地玩家对一至三名电脑玩家。
- 进入对局后，所有参与者先各掷一颗六面骰决定行动顺序；同点参与者组成小组重掷，直到组内顺序确定。
- 座次锁定后按最终顺序逐人选择起始道具；权威端为每名参与者分别从当前道具池无放回抽取三件候选，同一名参与者的三件不重复，不同参与者的候选允许相同也允许不同。
- 不建立角色属性、角色技能或养成系统。所有检定只由骰子、道具和临时规则修正决定。
- 对局中只公开本地玩家持有的道具；其他玩家的 HUD 不显示道具名称、持有状态或保密占位文字，仅在实际触发或主动使用时连同玩家名和效果公开。
- 本地玩家通过事件获得道具后在中央确认：已有道具时二选一并在 5 秒后自动保留当前勾选项；原道具栏为空时显示单张新道具并在 3 秒后自动关闭。单卡确认是本地表现，不广播给其他玩家。
- 对局 HUD 按最终行动顺序从上到下排列；回合交接时，当前行动者提示在棋子移动、碰撞及相关效果演出全部结束后再切换。
- 玩家在开局时可以选择棋子皮肤；皮肤只改变外观和动画资源，不影响规则与数值。
- Web 客户端采用 React + Vite，React 负责界面，PixiJS 负责棋盘场景；在线阶段使用独立 Node.js + TypeScript 游戏服务器。
- 游戏规则由独立状态机管理，不依赖 React 组件或 PixiJS 显示对象。
- 规则命令、状态快照、随机结果和内容 ID 必须可序列化，为后续在线房间、状态同步和断线恢复保留稳定边界。
- 地图共有 65 格；喧声屋是覆盖第 63、64、65 格的终点建筑区域。
- 移动结算后的落点进入第 63、64、65 任意一格时立即获胜。
- 桌面端基础 UI 状态、棋盘布局和美术风格以 `example_screenshots/Screenshot_2026-07-27-17-48-45-140_com.netease.ywzh.jpg` 为主参考。
- 截图只作为玩法和视觉参考，不直接作为最终棋盘背景。
- 默认地图保留参考图中的 65 格顺序和地标相对位置。
- 引擎通过地图配置支持以后切换地图、改变格子数量和设置不同胜利格；首版不提供地图选择界面。
- 第一阶段只建立声音接口，不接入音频资源或具体播放库。

## 正式技术基线

以下方案作为重写的正式技术基线：

- React + Vite 负责 Web 应用外壳，React Router 负责客户端页面路由，React 负责玩家面板、卡牌、弹窗、设置和结算。
- PixiJS v8 负责棋盘、棋子、骰子、镜头和视觉效果。
- XState v5 负责回合与事件状态机。
- tween.js 配合 PixiJS ticker 负责场景补间动画。
- 独立 Node.js + TypeScript 游戏服务器负责未来的房间、WebSocket、在线 AI 和权威规则结算。
- 音频通过自定义 `AudioPort` 接口隔离；第一阶段使用无声音实现。
- Vitest 负责规则和组件测试。

## 第一阶段不包含

- 竖屏、手机与平板布局。
- 在线房间、匹配和服务器部署（首阶段不交付，但网络兼容边界必须在首阶段建立）。
- 角色属性、角色技能和养成系统。
- 内容编辑器和用户自制事件。
- 对原游戏全部事件、道具和美术的逐项复刻。
- 实际音效、背景音乐和音频播放库。

角色系统属于永久不做的范围，不作为后续玩法扩展预留；棋子皮肤系统独立存在且只负责外观。玩法扩展明确包括新地图、不同格数、事件、道具、参与人数和模式规则，后续在线联机也属于正式路线图。

## 名词约定

- **移动骰**：决定棋子本回合移动距离的两颗骰子。
- **检定骰**：事件结算时掷出的两颗骰子，不导致普通移动。
- **事件格**：落入后触发三选一事件的格子。
- **地标**：棋盘上的大型场景物件，可与事件格重合。
- **回合**：一名参与者从开始行动到效果结算完成的全过程。
- **轮次**：按本局座次，所有仍在局内的参与者各完成一次正常回合。
- **座次投掷**：开局使用单颗六面骰决定行动顺序的流程；只让同点小组重掷，点数始终按从高到低排列。
