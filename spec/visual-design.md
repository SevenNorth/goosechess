# 视觉与交互规格

## 1. 设计方向

整体延续参考截图中的旧纸棋盘、手绘涂鸦、拼贴卡片和强烈洋红强调色，但不直接使用截图作为背景。

目标不是完全复刻原界面，而是保留其“临时画在旅馆桌上的冒险棋”气质，同时提升可读性和动画完成度。

### 1.1 主参考图

桌面端基础 UI 状态、棋盘布局与风格以以下图片为主参考：

`example_screenshots/Screenshot_2026-07-27-17-48-45-140_com.netease.ywzh.jpg`

该截图确定以下基线：

- 棋盘位于画面中央并占据绝大部分空间。
- 玩家列表纵向排列在左上区域。
- 轮次与系统操作位于右侧。
- 当前道具在右下区域以倾斜卡牌呈现。
- 双骰在棋盘下方偏中间区域滚动。
- 默认棋盘采用横向、环绕后进入内圈的 65 格路线。
- 地标直接画在纸面地图上，格子围绕地标穿行。
- 当前行动者使用头像气泡、彩色描边和棋子高亮表示；头像气泡显示玩家标识或皮肤缩略图，不承载角色属性。

实现时可以为适应网页交互调整间距和信息层级，但不得改变棋盘的主要路线结构、地标相对位置和整体纸面构图。截图只用于设计参考，不作为运行时棋盘底图。

## 2. 桌面布局

第一阶段仅考虑横向桌面布局，不设计竖屏断点或竖屏替代棋盘。

```text
┌────────────────────────────────────────────────────────────┐
│ 品牌 / 当前局信息                         日志  设置  重开 │
├────────────┬───────────────────────────────┬───────────────┤
│ 玩家状态   │                               │ 当前回合      │
│            │         PixiJS 棋盘           │ 双骰          │
│ 电脑状态   │                               │ 道具槽        │
│            │                               │ 主要操作      │
├────────────┴───────────────────────────────┴───────────────┤
│ 临时状态、规则修正与最近动态                              │
└────────────────────────────────────────────────────────────┘
```

- 棋盘是第一视觉焦点，占可用宽度约 68% 至 74%。
- 左右面板保持安静，不使用大量卡片边框。
- 事件选择使用覆盖棋盘的舞台式弹层。
- 在最低支持尺寸 `1280 x 720` 下，不允许出现页面纵向滚动。

## 3. 棋盘

### 3.1 材质

- 主体是偏灰的旧纸张，避免过度黄色或复古棕色。
- 边缘有磨损、折痕、胶带和少量墨迹。
- 桌面背景比棋盘更暗，让棋盘自然成为焦点。
- 纸张纹理必须来自位图资源，不使用纯 CSS 渐变冒充主要材质。

### 3.2 路线

- 默认地图的 65 个格子沿手绘路线排列，保持轻微大小和旋转差异。
- 普通格使用低对比墨线。
- 事件格使用鹅形符号和暖红底色。
- 当前棋子未来可达范围可以短暂高亮，但不能常驻发光。
- 起点可以比普通格大约 25%；喧声屋使用一座建筑统一包围第 63、64、65 三格，而不是把其中某一格单独画成终点。

### 3.3 地标

地标应使用独立透明图片或纹理图集，不画进棋盘底图，以便添加层次、轻微视差和事件动画。

每个地标需要：

- 默认静态图。
- 鼠标悬停或镜头经过时的轻微反应。
- 触发事件时的强调动画。
- 简短地标标签。

大黄狗需要明确表现为黄色犬类形象，避免再次被误读为嘴或其他图形。

### 3.4 移动路线预览

移动骰定格并显示点数之和后，先播放路线预览，再移动棋子：

1. 从棋子当前格中心开始，沿实际移动格序逐步绘制路线。
2. 路线一直延伸到本回合的最终目标格；发生终点折返时，路线必须表现出到达第 65 格后反向延伸的过程。
3. 路线绘制完成后，在目标格外绘制一个清晰圆圈，并轻微脉冲一次。
4. 路线线条淡出并完全消失。
5. 棋子开始逐格跳跃，目标圆圈保留到棋子落地后再淡出。

路线使用当前行动者的识别色。玩家为洋红色，电脑为蓝色；线宽在 `1600 x 900` 逻辑画布中建议为 5 至 7 像素。路线应位于格子上方、棋子下方，不得遮挡骰子或地标名称。

绘制动画按路径总长度匀速推进，不能一次性显示完整路线。预览期间锁定掷骰和道具输入。

## 4. 棋子

- 棋子是带底座的手工小模型，而不是圆形头像标记。
- 玩家使用洋红描边，电脑使用蓝绿色或蓝色描边。
- 当前行动者有轻微呼吸和纸面阴影变化。
- 同一格出现多个棋子时横向错位，不重叠遮挡。
- 玩家在开局时选择棋子皮肤；皮肤只能改变模型、贴图和自身动画，不能改变玩家识别色。
- 首版至少提供 4 款可直接选择的皮肤，不设置解锁、稀有度、升级或付费状态。

## 5. 镜头

桌面端默认显示完整棋盘。

镜头只做小范围演出：

- 掷骰前向当前棋子轻推 3% 至 5%。
- 移动期间让棋子保持在安全区域，但不大幅平移整张棋盘。
- 触发地标时短暂推近，事件卡出现后恢复。
- 获胜时推近包含第 63、64、65 格的完整喧声屋区域，并提高背景虚化或压暗程度。

用户可以通过设置关闭镜头运动。

## 6. 骰子演出

- 两颗骰子在棋盘右下方的空白桌面区域出现。
- 骰子具有不同明暗配色，但点数符号保持高对比。
- 动画包含抛出、旋转、两次轻微弹跳和定格。
- 总时长建议为 700 至 950 毫秒。
- 定格后先读取单骰点数，再显示总点数，避免结果一闪而过。
- 检定骰使用同一套动画，但在事件弹层前方播放。

## 7. 移动与碰撞

### 7.1 逐格移动

- 棋子必须沿计算好的格子路径逐格跳跃，不允许从起点直接补间或瞬移到终点。
- 每一跳采用低抛物线轨迹：起跳时轻微压缩，空中稍微上提和前倾，落地时短暂回弹。
- 棋子阴影留在纸面并随高度缩小、变淡，强化离地感。
- 普通单格跳跃建议为 110 至 150 毫秒；长距离移动可以将中间格压缩到 90 毫秒，但起跳、折返和最后一格保持完整节奏。
- 路径转弯时棋子朝下一格方向轻微旋转；到达第 65 格折返时必须有一次清楚的停顿与转身。
- 到达目标格后先稳定落地，再进入碰撞、胜利或事件演出。

### 7.2 碰撞

- 行动棋子在落点前稍微蓄力。
- 碰撞瞬间暂停约 80 毫秒。
- 使用冲击线、纸屑或震动表达结果。
- 被撞棋子沿较快路径回到行动者起始位置。
- 防御道具生效时用清晰的阻挡动画取代退回动画。

## 8. 事件卡

- 三张牌并排出现，宽度与高度稳定，最长标题不能撑大卡片。
- 每张牌包含类别、插画、标题、叙事文本、检定门槛或直接效果摘要。
- 悬停时卡片上移并轻微旋转，不使用大幅缩放。
- 选择后另外两张牌淡出，所选卡片移到中央。
- 骰子检定在卡片下方完成，随后翻出成功或失败结果。

事件插画应使用统一的黑色速写风格，并允许使用一处事件强调色。

## 9. 色彩

建议基础色：

- 桌面深灰：`#171916`
- 纸张灰米色：`#DED8C4`
- 墨色：`#292C27`
- 玩家洋红：`#E82F73`
- 电脑蓝色：`#3977C5`
- 事件青绿：`#2BAF9C`
- 风险珊瑚红：`#D95E4A`
- 奖励黄色：`#D4A43A`

不得让整个界面被米色、深蓝或单一洋红色主导。纸张、桌面、玩家、电脑和事件必须形成清楚层次。

## 10. 动效时长

| 动作 | 建议时长 |
|---|---:|
| 按钮反馈 | 100-160 ms |
| 卡牌出现 | 240-320 ms |
| 卡牌选择 | 300-420 ms |
| 骰子滚动 | 700-950 ms |
| 路线绘制 | 280-450 ms |
| 目标圈强调 | 180-260 ms |
| 路线淡出 | 100-160 ms |
| 单格移动 | 110-150 ms；长距离中间格可压缩到 90 ms |
| 碰撞停顿 | 60-100 ms |
| 地标推镜 | 350-500 ms |
| 胜利演出 | 1600-2400 ms |

所有关键动画需要支持“加速表现”设置。关闭动画时仍保留最短的状态反馈，避免界面瞬间跳变导致玩家无法理解结果。

## 11. 资源清单

首个完整版本至少需要：

- 1 张棋盘纸张底图。
- 1 张桌面背景。
- 9 个地标透明资源。
- 至少 4 款棋子皮肤及其阴影和动画资源。
- 2 套骰子贴图或可程序化组合的骰子面。
- 12 张道具插画。
- 24 张事件插画。
- 碰撞、移动、检定、获得道具和胜利特效。
- 为鼠标悬停、掷骰、移动、碰撞、翻牌和胜利预留声音提示 ID；第一阶段不制作或接入声音文件。

资源制作可以分阶段进行。首个核心体验样片只要求一段棋盘、两个地标、两枚棋子、骰子和三张事件插画达到最终质量。
