# 视觉与交互规格

## 1. 设计方向

整体延续参考截图中的旧纸棋盘、手绘涂鸦、拼贴卡片和强烈洋红强调色，但不直接使用截图作为背景。

目标不是完全复刻原界面，而是保留其“临时画在旅馆桌上的冒险棋”气质，同时提升可读性和动画完成度。

所有可阅读的静态界面文字以 `14px` 为最小字号，包括事件与道具说明、HUD、弹窗、日志、设置、棋盘格编号和图例。空间不足时必须增加容器尺寸、允许合理换行或调整布局，不得把静态文字压缩到 `14px` 以下；骰子结果等动态演出数字按各自视觉规格处理，不受该最小字号限制。

该截图确定以下基线：

- 棋盘位于画面中央并占据绝大部分空间。
- 玩家列表纵向排列在左上区域。
- 玩家列表显示本局实际启用的 2 至 4 个座位，每行包含座位色、棋子缩略图、显示名和当前道具图标。
- 轮次与系统操作位于右侧。
- 当前道具在右下区域以倾斜卡牌呈现。
- 双骰在棋盘下方偏中间区域滚动。
- 默认棋盘采用横向、环绕后进入内圈的 65 格路线。
- 地标直接画在纸面地图上，格子围绕地标穿行。
- 当前行动者使用头像气泡、彩色描边和棋子高亮表示；头像气泡显示玩家标识或皮肤缩略图，不承载角色属性。

实现时可以为适应网页交互调整间距和信息层级，但不得改变棋盘的主要路线结构、地标相对位置和整体纸面构图。截图只用于设计参考，不作为运行时棋盘底图。

## 2. 桌面布局

第一阶段仅考虑横向桌面布局，不设计竖屏断点或竖屏替代棋盘。

```text
┌────────────────────────────────────────────────────────────┐
│ 参与者列表                                   菜单 / 日志 │
│ ┌────────┐                                               │
│ │座位 1  │        当前行动 / 地标横幅         轮次       │
│ │座位 2  │                                               │
│ │座位 3  │              PixiJS 棋盘                      │
│ │座位 4  │                                               │
│ └────────┘              双骰               当前道具卡    │
│                    临时提示 / 操作层                      │
└────────────────────────────────────────────────────────────┘
```

- 棋盘是第一视觉焦点，尽量保留参考录像中铺满画面的纸张构图，不另设常驻右侧栏压缩棋盘。
- 参与者列表悬浮在棋盘左上，轮次悬浮在右侧；两者都使用低透明深色底以保证纸面上的可读性。未启用座位不显示空行。
- 事件选择使用覆盖棋盘的舞台式弹层。
- 在最低支持尺寸 `1180 x 680` 下，对局舞台不允许出现页面纵向滚动。

### 2.1 基础 UI 状态

- **对局准备**：顶部保留品牌区，右上角显示带头像、昵称和“本地档案”来源的个人信息入口；主区域使用三段式选择器选择 `1v1`、`1v2` 或 `1v3`，并预览本局一至三名电脑棋手。
- **个人信息 sidebar**：点击顶部入口后，从顶栏下方的页面最右侧展开固定宽度 sidebar，显示昵称和棋子外观。展开时主配置区向左收窄，不得覆盖人数选择、电脑阵容或开始按钮；关闭后主配置区恢复居中。
- **昵称输入**：输入框同步显示当前宽度与上限；中文计 2、英文计 1，总宽度上限 14。无效状态使用错误色并禁用开始按钮，不能通过裁切隐藏错误。
- **电脑阵容**：电脑使用主题昵称和独立头像条目，不显示“电脑 1/2/3”作为主名称；刷新按钮使用图标和 tooltip，刷新后预览与实际对局必须一致。
- **棋盘地图列表**：准备页在在线房间区域下方展示当前内容版本可用的地图卡，卡片使用地图真实纸张与地标资源，显示地图名、路线格数和地标数量；点击整张卡进入独立地图预览页。
- **地图预览**：独立页面只保留返回入口、地图名、路线格数、地标数量和铺满剩余视口的 Pixi 棋盘，不创建参赛棋手、棋子、座次、道具、骰子或回合 HUD。
- **座次投掷**：进入对局后先使用居中舞台显示全部参与者、当前单骰点数和暂定顺序。每名参与者使用一张并排的竖版人物卡，卡内从上到下依次为昵称、与棋盘一致的棋子外观和座次骰；名次及等待投掷、同点组、暂定状态作为角标保留。同点参与者高亮为重掷小组，最终顺序明确后进入起始道具选择。
- **起始道具选择**：按最终座次逐人展示当前参与者独立抽取的三张候选卡；标题明确显示参与者名称和选择进度，本地玩家选择并确认，电脑玩家显示短暂等待状态。所有人完成后再进入第一回合。
- **等待行动**：左上按最终行动顺序从上到下显示本局全部参与者，当前行动者使用座位色条、棋子描边和头像气泡共同强调。回合权威状态推进后，HUD 与“当前行动”横幅仍保持上一位玩家，直到棋子移动、碰撞及相关效果演出结束才切换到下一位。
- **暂停状态**：左上参与者条目使用独立沙漏徽标显示剩余暂停回合数。轮转遇到暂停玩家时，先将当前行动高亮切到该玩家；棋盘中央以不带卡片背景的座位色标记、玩家名和大号沙漏明确展示被暂停者，沙漏旋转一整圈后“暂停本回合”切换为“剩余 N 回合”，左上数字同步减一。多个暂停玩家连续被跳过时逐个演出，全部完成后才高亮实际可行动玩家。
- **回合开始**：棋盘中央短暂出现“某玩家的回合开始”横幅；不能只靠颜色传达当前行动者。
- **可投骰**：两颗可点击的 3D 骰子停靠在棋盘下方偏中间，取代独立文字按钮；当前主动道具仍在右下可点击。本回合尚未投掷时不显示点数或合计，骰子只保留中性的立体外观。
- **道具详情**：棋盘压暗，中央显示道具说明、取消和确认按钮；需要目标的道具在确认前显示合法玩家单选列表，包含玩家名、座位色和当前位置，未选择时禁用确认。
- **移动表现**：普通投掷定格后只在中央放大显示红色总点数；存在移动修正时改为显示“骰子合计 ± 道具效果”。路线开始绘制时只把真实移动距离缩小并飞到棋盘右下角，保持到逐格跳跃结束后消失。期间锁定玩法输入。
- **遭遇地标**：中央先播放地标名称横幅，再进入事件选择层。
- **事件选择/检定**：三张卡并排，选中后其余卡变暗；检定骰在卡牌层前方滚动并给出明确成功或失败结果。
- **事件获得道具**：事件结果确认后在棋盘中央展示道具确认层。已有道具时并排显示当前与新道具，5 秒倒计时结束后自动保留当前勾选项，切换选择不能重置计时；原道具栏为空时只展示新道具卡，3 秒后自动关闭。两种弹窗都允许提前确认。
- **终局**：棋盘压暗并转为横向地标进度舞台，再显示名次和重新开局操作。

## 3. 棋盘

### 3.1 材质

- 主体是偏灰的旧纸张，避免过度黄色或复古棕色。
- 边缘有磨损、折痕、胶带和少量墨迹。
- 桌面背景比棋盘更暗，让棋盘自然成为焦点。
- 纸张纹理必须来自位图资源，不使用纯 CSS 渐变冒充主要材质。

### 3.2 路线

- 默认地图的 65 个格子沿手绘路线排列，保持轻微大小和旋转差异。
- 普通格使用低对比墨线。
- 事件格使用鹅形符号和暖红底色。
- 当前棋子未来可达范围可以短暂高亮，但不能常驻发光。
- 起点可以比普通格大约 25%；喧声屋使用一座建筑统一包围第 63、64、65 三格，而不是把其中某一格单独画成终点。

### 3.3 地标

地标应使用独立透明图片或纹理图集，不画进棋盘底图，以便添加层次、轻微视差和事件动画。

每个地标需要：

- 默认静态图。
- 鼠标悬停或镜头经过时的轻微反应。
- 触发事件时的强调动画。
- 简短地标标签。

大黄狗需要明确表现为黄色犬类形象，避免再次被误读为嘴或其他图形。

### 3.4 移动路线预览

移动骰定格并显示点数之和后，先播放路线预览，再移动棋子：

1. 从棋子当前格中心开始，沿实际移动格序逐步绘制路线。
2. 路线一直延伸到本回合的最终目标格；发生终点折返时，路线必须表现出到达第 65 格后反向延伸的过程。
3. 路线绘制完成后，在目标格外绘制一个清晰圆圈，并轻微脉冲一次。
4. 路线线条淡出并完全消失。
5. 棋子开始逐格跳跃，目标圆圈保留到棋子落地后再淡出。

路线使用当前行动者的座位识别色，并统一加高亮外沿；当前本地可操作状态可以额外使用洋红强调。线宽在 `1600 x 900` 逻辑画布中建议为 5 至 7 像素。路线应位于格子上方、棋子下方，不得遮挡骰子或地标名称。

绘制动画按路径总长度匀速推进，不能一次性显示完整路线。预览期间锁定掷骰和道具输入。

## 4. 棋子

- 棋子是带底座的手工小模型，而不是圆形头像标记。
- 棋子使用所属座位的高对比描边，控制方式不能从颜色推断。
- 当前行动者有轻微呼吸和纸面阴影变化。
- 单枚棋子独占普通路线格并严格居中。发生碰撞时，移动棋子先落地，原占位棋子随后飞回本次移动的起点；碰撞保护生效时改为移动棋子弹回。
- 玩家在准备页的个人信息 sidebar 选择棋子皮肤；皮肤只能改变模型、贴图和自身动画，不能改变玩家识别色。
- 首版至少提供 4 款可直接选择的皮肤，不设置解锁、稀有度、升级或付费状态。

## 5. 镜头

桌面端默认显示完整棋盘。

镜头只做小范围演出：

- 掷骰前向当前棋子轻推 3% 至 5%。
- 移动期间让棋子保持在安全区域，但不大幅平移整张棋盘。
- 触发地标时短暂推近，事件卡出现后恢复。
- 获胜时推近包含第 63、64、65 格的完整喧声屋区域，并提高背景虚化或压暗程度。

用户可以通过设置关闭镜头运动。

## 6. 骰子演出

- 回合等待本地玩家行动时，两颗骰子停靠在原投掷按钮位置；整组骰子是带有“投掷双骰”可访问名称的按钮。
- 点击后骰子从停靠位移动到棋盘中央，在不遮挡常驻 HUD 的上层透明 3D 画布中滚动；不再在棋盘右下角额外绘制一组骰子。
- 骰子具有不同明暗配色，但点数符号保持高对比。
- 动画包含抛出、旋转、两次轻微弹跳和定格。
- 两颗骰子应从当前停靠姿态连续起滚，分别沿略有差异的抛物线移动；主落地后再进行两次高度递减的弹跳，并以衰减摇摆自然停稳。最终权威点数必须从固定的翻滚结束姿态平滑插值，不得在最后一帧突然翻面。
- 两颗骰子的底部停靠中心位置保持左右各约 0.62 个逻辑单位；飞向中央时应平滑展开到左右各约 1.0 个逻辑单位，并保留轻微外摆，使高速斜向旋转期间模型轮廓不得交叠。
- 普通速度下总时长建议为 2350 至 2450 毫秒，其中前约 76% 用于滚动与定格，后约 24% 保持权威结果。减少动态效果时不得把关键反馈压缩成瞬间切换，应使用相同时长的低旋转、低弹跳版本。
- 动画只能读取权威 `dice-roll` 表现提示，不得自行生成点数；定格后用符合棋盘事件格配色的红色大号数字显示总点数，不再重复显示单骰加法算式。
- `dice-roll` 同时包含原始骰面和最终骰面。存在骰面上限或下限时，先让原始结果停留可读，再让每颗不满足条件的骰子闪光并连续转到边界点数；不得直接替换贴图或瞬间翻面。
- 固定移动 8 必须由权威端指定一颗骰子闪光转面，最终两颗可见骰子的和为 8。移动加减修正不改变骰面，中央使用同一红色风格展示“基础合计 ± 修正”，右下角只显示包含修正后的真实距离。
- 原始骰面停留、逐骰修正和最终结果停留全部属于 `rolling` 阶段；最后一项完成前不得开始路线或棋子移动。
- 中央总点数使用约 216 像素的前景文字和 280 x 280 像素稳定容器，层级高于 3D 骰子并覆盖在两骰中央；飞到右下角时再缩小到与纸张留白匹配的尺寸。
- 骰子应在滚动阶段前约 28% 完成向桌面中央的位移，途中旋转由慢加速到快；到达中央后保持高速旋转到约 67%，随后在约 80% 前连续减速，最后平滑进入权威点数姿态。各阶段角速度必须连续，不得突然加速或刹停。
- 骰子滚动到权威点数后，中央大号总点数至少保留约 850 毫秒，再进入路线阶段，避免结果一闪而过。
- 路线开始绘制时，总点数以约 1400 毫秒的弧线动画进入棋盘纸张右下角的空白区域；飞行中应有抬升、旋转、缩放和运动投影，不能直接切换位置。减少动态效果时使用约 1000 毫秒、无抬升和旋转的简化飞行，不允许压缩为瞬间切换。坐标必须跟随纸张边界，宽屏下不能落到外侧桌面或黑色边栏。道具卡在这段表现期间暂时收起，棋子移动完成后清除总点数并恢复道具卡。
- 检定骰使用同一套动画，但在事件弹层前方播放。

### 道具使用演出

- 左侧参与者 HUD 只显示本地玩家的道具名称；其他玩家不显示道具名称、是否持有或“道具保密”等占位文字，避免从文案变化推断隐藏状态。
- 所有主动与被动道具消耗都必须由权威 `item-use` 提示驱动，并在实际效果对应的移动、检定、暂停或碰撞表现之前插入，不得仅依赖本地按钮状态推断。
- 对玩家生效的主动道具在详情弹窗中列出所有权威合法目标；确认前必须手动勾选。演出中的玩家标题同时说明“作用于某玩家”，让使用者和观察者都能确认实际目标。
- 本地玩家的卡片从右下道具栏飞到棋盘中央；其他玩家的主动或被动卡片从画面上方飞入。中央同时显示玩家名、主动/被动类型、道具名称和完整效果说明。
- 事件直接获得和已有道具时的二选一确认都仅属于本地信息反馈，不使用 `item-use` 表现提示，也不向其他玩家播放卡片入场或广播动画；确认期间暂停后续电脑演出，关闭后继续。
- 普通 `1x` 演出约 3800 毫秒：前 22% 飞入，随后将完整卡片留在中央供阅读；约 64% 开始沿中线自上而下绘制竖直锯齿裂口，约 76% 后左右两半再向两侧分开并淡出。演出结束后才继续播放道具效果。
- 系统启用减少动态效果时降低飞行、分离位移和旋转幅度，但必须保留完整展示时长、竖向裂口和左右分离三个阶段，不能压缩为短暂闪现或省略撕裂反馈。

## 7. 移动与碰撞

### 7.1 逐格移动

- 棋子必须沿计算好的格子路径逐格跳跃，不允许从起点直接补间或瞬移到终点。
- 每一跳采用低抛物线轨迹：起跳时轻微压缩，空中稍微上提和前倾，落地时短暂回弹。
- 棋子阴影留在纸面并随高度缩小、变淡，强化离地感。
- 普通单格跳跃建议为 110 至 150 毫秒；长距离移动可以将中间格压缩到 90 毫秒，但起跳、折返和最后一格保持完整节奏。
- 路径转弯时棋子朝下一格方向轻微旋转；到达第 65 格折返时必须有一次清楚的停顿与转身。
- 到达目标格后先稳定落地，再进入碰撞、胜利或事件演出。

### 7.2 碰撞

- 行动棋子在落点前稍微蓄力。
- 碰撞瞬间暂停约 80 毫秒。
- 使用冲击线、纸屑或震动表达结果。
- 被撞棋子沿较快路径回到行动者起始位置。
- 防御道具生效时用清晰的阻挡动画取代退回动画。

## 8. 事件卡

- 三张牌并排出现，宽度与高度稳定，最长标题不能撑大卡片。
- 每张牌包含类别、插画、标题、叙事文本、检定门槛或直接效果摘要。
- 悬停时卡片上移并轻微旋转，不使用大幅缩放。
- 选择后另外两张牌淡出，所选卡片移到中央。
- 骰子检定在卡片下方完成，随后翻出成功或失败结果。
- 原录像中的“智力事件”标签和属性修正条不复刻。网页版改为骰子检定类别，并直接显示骰组、门槛与成功/失败效果。

事件插画应使用统一的黑色速写风格，并允许使用一处事件强调色。

## 9. 色彩

建议基础色：

- 桌面深灰：`#171916`
- 纸张灰米色：`#DED8C4`
- 墨色：`#292C27`
- 当前行动强调洋红：`#E82F73`
- 座位蓝色：`#3977C5`
- 事件青绿：`#2BAF9C`
- 风险珊瑚红：`#D95E4A`
- 奖励黄色：`#D4A43A`

最多四个座位使用珊瑚红、青绿、蓝色和黄色等可区分色；洋红只作为当前可操作和选中强调，不绑定“人类玩家”身份。

不得让整个界面被米色、深蓝或单一洋红色主导。纸张、桌面、参与者和事件必须形成清楚层次。

## 10. 动效时长

| 动作 | 建议时长 |
|---|---:|
| 按钮反馈 | 100-160 ms |
| 卡牌出现 | 240-320 ms |
| 卡牌选择 | 300-420 ms |
| 骰子滚动与定格 | 1750-1850 ms |
| 中央结果停留 | 550-650 ms |
| 结果飞向右下角 / 路线绘制 | 1350-1450 ms |
| 目标圈强调 | 180-260 ms |
| 路线淡出 | 100-160 ms |
| 单格移动 | 110-150 ms；长距离中间格可压缩到 90 ms |
| 碰撞停顿 | 60-100 ms |
| 地标推镜 | 350-500 ms |
| 胜利演出 | 1600-2400 ms |

所有关键动画需要支持“加速表现”设置。关闭动画时仍保留最短的状态反馈，避免界面瞬间跳变导致玩家无法理解结果。

## 11. 资源清单

首个完整版本至少需要：

- 1 张棋盘纸张底图。
- 1 张桌面背景。
- 9 个地标透明资源。
- 至少 4 款棋子皮肤及其阴影和动画资源。
- 2 套骰子贴图或可程序化组合的骰子面。
- 12 张道具插画。
- 24 张事件插画。
- 碰撞、移动、检定、获得道具和胜利特效。
- 为鼠标悬停、掷骰、移动、碰撞、翻牌和胜利预留声音提示 ID；第一阶段不制作或接入声音文件。

资源制作可以分阶段进行。首个核心体验样片只要求一段棋盘、两个地标、四枚棋子、骰子和三张事件插画达到最终质量。

## 12. 终局舞台

- 胜利触发后锁定操作，保留最后落点约 300 至 500 毫秒，再压暗棋盘。
- 将地标缩成一条横向进度线，本局全部棋子按最终位置投影到线上；冠军位于喧声屋一端并使用“获胜”爆发字效。
- 名次列表显示座位色、棋子皮肤、名称和名次，不显示角色等级、货币、经验或养成奖励。
- “再来一局”创建新 `gameId`；联机局需要等待房主或房间准备流程，不能在客户端单方面重置权威状态。
